# market/ — คำแปลไทยของตลาดปลั๊กอิน DSH

ชุดคำแปลสำหรับ **ตลาดปลั๊กอิน DSH** (แคตตาล็อกปลั๊กอินจาก awesome-dsh-plugin)
แยกออกมาเป็นไฟล์ ๆ เพื่อให้เพิ่มคำแปลได้เรื่อย ๆ ทีละหมวด โดยไม่ต้องแตะตัวตลาด

## ไฟล์อะไรบ้าง

| พาธ | หน้าที่ |
|---|---|
| `build-th.mjs` | ตัวรวมคำแปลเข้าตลาด — เติมชื่อตลาด คำอธิบายตลาด ชื่อ 23 หมวด และคำอธิบายปลั๊กอินที่แปลแล้ว |
| `data/th/<หมวด>.json` | คำอธิบายปลั๊กอินภาษาไทย แยกไฟล์ตามหมวด |
| `glossary.th.md` | ทะเบียนคำศัพท์: คำที่ห้ามแปล คำที่ต้องใช้ให้ตรงกันทุกหมวด และคำที่เคยชนกัน |

## สถานะคำแปล

| ส่วน | สถานะ |
|---|---|
| ชื่อตลาด + คำอธิบายตลาด | ไทยแล้ว |
| ชื่อ **23 หมวด** | ไทยครบ |
| คำอธิบายปลั๊กอิน | **57 รายการ** — `agi` 45, `wsl` 12 |

## วิธีสร้างไฟล์ตลาด

ต้องมีไฟล์ `index.json` ต้นฉบับ (format 1 ของ awesome-dsh-plugin) ก่อน:

```bash
node build-th.mjs <index-ต้นฉบับ>.json <index-ปลายทาง>.json
```

ตัวรวมจะตรวจให้เองว่าชื่อปลั๊กอินมีจริงและอยู่หมวดถูก — ถ้าชื่อผิดหรือใส่ผิดหมวด
จะ **ข้ามแล้วรายงาน** ไม่ทำให้ทั้งตลาดพัง

## วิธีเพิ่มคำแปลหมวดใหม่

1. สร้าง `data/th/<ชื่อหมวด>.json` โดยใช้ **ชื่อปลั๊กอินเป็นคีย์**

   ```json
   { "dsh-wsl-tool": "ขยายขอบเขตการทำงานของ DSH เข้าไปใน WSL: ..." }
   ```

2. รัน `build-th.mjs` อีกครั้ง — คำแปลจะถูกเติมลง `description.th`

## กฎการแปล

1. **ห้ามแปลชื่อปลั๊กอิน ชื่อไฟล์ ชื่อพาธ ชื่อคำสั่ง** และศัพท์แบรนด์ (`dsh`, `MCP`, `Cordis`, `WSL`, `PowerShell`, `cron`, `SQLite`, `RRF`)
2. คำศัพท์พื้นฐานให้ใช้ตรงกันทุกหมวด — ดู [glossary.th.md](glossary.th.md) เช่น agent = เอเจนต์, session = เซสชัน, turn = เทิร์น, workspace = เวิร์กสเปซ
3. คำแปลเป็น **ฟิลด์ซ้อน** (`description.th`) ไม่ทับต้นฉบับ `en`/`zh`
4. ใช้ Unicode แบบ NFC และห้ามมีอักษรจีนในค่าภาษาไทย
