สถานะ: ร่าง รอตรวจ

## ปัญหา

ปลั๊กอินมีภาษาไทยสองชุดคือ `th` (ไทยธรรมดา) และ `th-roast` (ไทยกวนตีน) ที่เพิ่งเพิ่มใน 1.2.0
การวัดจากไฟล์จริง `lib/client.js` (946,015 ไบต์) เจอปัญหาสี่ข้อ

1. **ชุดกวนคุณภาพไม่สม่ำเสมอ** — 4,601 คีย์ มี 4,129 คีย์ที่ต่างจากไทยธรรมดา แต่ 4,034 คีย์ในนั้น
   เกิดจากกฎเติมคำท้ายอัตโนมัติ (` นะ`, ` ครับ`, ` สิ`, ` นะเออ`) ไม่ใช่การเขียนใหม่
   ที่เขียนด้วยมือจริงมี 95 คีย์เท่านั้น ผลคือปุ่มสั้น ๆ กลายเป็น `สถานะ ครับ`, `หมวดหมู่ข้อเสนอแนะ นะ`
   และมี 7 เคสต่อท้ายซ้ำ และ 1 เคสพังคือ `workspace.toast.archivedOr` จาก `" หรือ "` เป็น `" หรือ สิ "`
2. **ขนาดบันเดิลโตเท่าตัว** — จาก 444,649 ไบต์เป็น 946,015 ไบต์ เพราะเก็บคำแปลกวนครบทุกคีย์
   ทั้งที่ 4,034 คีย์เป็นข้อความเดิมบวกคำท้าย
3. **ยังไม่ได้ติดตั้งเวอร์ชันใหม่ในเครื่อง** — โปรไฟล์ `web` ลิงก์ไปที่
   `/storage/emulated/0/AI storage/dsh-thai-locale` ซึ่งยังเป็น `lib/client.js` ของ 1.1.0
   (ขนาด 444,649 ไบต์, แก้ล่าสุด 12 พ.ย.) ขณะที่ `node_modules/dsh-thai-locale` รายงานเวอร์ชัน 1.1.0
4. **ไม่มีแท็กเวอร์ชัน 1.2.0** — commit `b79c487` ขึ้น GitHub แล้ว แต่ `git tag` มีแค่ถึง `1.1.0`

## ภาพรวม

ปรับชุดกวนให้คุณภาพสม่ำเสมอแทนการเติมคำท้ายทุกคีย์ ลดขนาดบันเดิลที่โตเกินจำเป็น
ติดตั้งเวอร์ชันใหม่ลงเครื่องจริง ทดสอบว่าใช้งานได้ แล้วออกเวอร์ชัน 1.3.0 พร้อมแท็กกำกับ

- คีย์ที่แสดงชุดกวนต้องอ่านแล้วไม่ขัดบริบท: ป้ายสั้น ปุ่ม ชื่อหน่วย ตัวเลข และข้อความโครงสร้าง
  (เช่น `" หรือ "`, `"{value}K"`) ต้องไม่ถูกเติมคำท้าย
- ลดขนาด `lib/client.js` กลับมาใกล้ระดับ 1.1.0 โดยไม่ทำให้ผู้ใช้เสียความสามารถ
- มีเครื่องมือในรีโปที่สร้างชุดกวนซ้ำได้ (`tools/` ) ไม่ใช่ JSON ก้อนที่แปะมือ
- ตัวตรวจจับข้อผิดพลาดของชุดกวนได้: คำท้ายซ้ำ, คำท้ายบนป้ายสั้น, placeholder ไม่ตรง, ข้อความไทยเสีย
- ติดตั้งลงเครื่องและยืนยันจาก UI จริงว่ามี `ไทย (กวนตีน)` ในตัวเลือกภาษา
- มีแท็ก `v1.3.0` บน GitHub ตรงกับ commit ที่ทดสอบแล้ว

## สิ่งที่ไม่ใช่เป้าหมาย

- ไม่แก้คำแปลไทยธรรมดา (`thDicts`) ยกเว้นคีย์ที่พิสูจน์ว่าเสีย
- ไม่เพิ่ม dependency ทุกชนิด (กฎเดิมของโปรเจกต์)
- ไม่แตะระบบแปลของ DSH เอง (`dsh-client-locale`) — ปลั๊กอินนี้เป็นผู้ใช้ ไม่ใช่ผู้แก้
- ไม่ทำคำแปลภาษาอื่นนอกจาก th/th-roast
- ไม่รับประกันว่าใช้ได้บน DSH Desktop เพราะยังไม่มีเครื่องทดสอบ

## ข้อจำกัดที่ยืนยันจากโค้ดจริง

- `apply(ctx)` ลงทะเบียนผ่าน `runtime.addLanguage` และ `runtime.register(ns, { th, "th-roast" })`
  เท่านั้น ปลั๊กอินไม่มีสิทธิ์แก้พจนานุกรมของแพ็กเกจอื่น
- `fallbackChain(start)` ใน `dsh-client-locale/lib/client.js` ไล่ตาม `fallback` แล้วบังคับต่อ `en`
  เสมอ ทำให้ `en` เป็นตัวจบสายบังคับ ลำดับแบบ `th → en → zh` ทำไม่ได้จริง
- `register()` โยน error ถ้า namespace+ภาษานั้นลงทะเบียนซ้ำ ฉะนั้นลงทะเบียนภาษาเดียวต่อ namespace ต่อรอบ
- ไฟล์ client ถูกโหลดเป็นบันเดิลเดียวผ่าน `window.__ModuleLoader__` การแยกพจนานุกรมออกเป็นไฟล์
  แล้ว `import`/`fetch` ตอนรันทำไม่ได้ (ไม่มีเครือข่าย และกฎโปรเจกต์ห้ามเพิ่มที่เก็บข้อมูลฝั่งเบราว์เซอร์)
  ทางเดียวคือย้ายข้อมูลออกไปเป็นไฟล์ JSON ที่เครื่องมืออ่านตอนพัฒนา ไม่ใช่ตอนรัน

## แผนเทคนิค

### โครงไฟล์หลังเปลี่ยน

```
lib/client.js                    ← บล็อก thRoastDicts ถูกสร้างจาก tools/roast-source/
tools/build-roast.mjs            ← ใหม่: รวมไฟล์ JSON ต่อ namespace เป็นบล็อกใน lib/client.js
tools/check-roast.mjs            ← ใหม่: ตรวจคุณภาพชุดกวนโดยเฉพาะ
tools/roast-source/STYLE.md      ← ใหม่: คู่มือโทนสำหรับผู้เขียน (และสำหรับ AI ที่ช่วยเขียน)
tools/roast-source/<namespace>.json  ← ใหม่: คำแปลกวนแยกไฟล์ต่อ namespace (75 ไฟล์)
tools/roast-source/_progress.json    ← ใหม่: สถานะว่างานเขียนถึง namespace ไหนแล้ว
tests/roast-coverage.test.mjs    ← ใหม่: ตรวจว่าไฟล์ต้นทางครบทุกคีย์และตรง placeholder
```

### การไหลของข้อมูล

```
tools/roast-source/*.json  ──build-roast──▶  lib/client.js (บล็อก thRoastDicts)
        │                                            │
        └──check-roast (ตรวจก่อนสร้าง) ──────────────┤
                                                     ▼
                                    DSH runtime: register(ns, { th, "th-roast" })
```

กฎสำคัญ: `lib/client.js` เป็นผลลัพธ์ ไม่ใช่แหล่งแก้ ห้ามแก้บล็อก `thRoastDicts` ด้วยมือ
เพราะรอบสร้างถัดไปจะทับ ถ้าต้องแก้คำ ให้แก้ที่ `tools/roast-source/<namespace>.json`

### ตัวตรวจ `tools/check-roast.mjs`

ตรวจทีละคีย์เทียบกับ `thDicts` และรายงานเป็นหมวด

| รหัส | เงื่อนไข | ระดับ |
|---|---|---|
| `PH` | ชุด placeholder `{...}` ไม่ตรงกับไทยเดิม | error |
| `CJK` | มีอักษรจีน/ญี่ปุ่น | error |
| `LAO` | มีอักษรลาว | error |
| `DUP` | คำท้ายซ้ำ (`นะ ครับ`, `ครับ ครับ`, `สิ สิ`) | error |
| `SHORT` | คีย์ไทยเดิมสั้นกว่า 8 ตัวอักษร แต่คำกวนยาวกว่ามาก (เติมท้ายบนป้ายสั้น) | warn |
| `SAME` | คำกวนเหมือนไทยเดิมทุกตัวอักษร | warn (แปลว่ายังไม่ได้เขียน) |
| `NFC` | ข้อความไม่อยู่ในรูป NFC | error |
| `MISSING` | คีย์ที่ `th` มีแต่ `th-roast` ไม่มี | error |

### คู่มือโทน `tools/roast-source/STYLE.md`

สรุปเป็นกฎที่ตรวจได้ ไม่ใช่คำอธิบายลอย ๆ

1. โทน: ประชดเบาแบบเพื่อน ไม่ด่าด้วยคำหยาบ ไม่ดูถูกผู้ใช้
2. ความยาว: ไม่เกิน 1.6 เท่าของไทยเดิม และไม่เกิน 120 ตัวอักษร
3. ห้ามแตะ: ชื่อแบรนด์ ชื่อคำสั่ง (`/plan`, `compact`, `Bash`), `{placeholder}`, ตัวเลข,
   ตัวย่อเทคนิค (`API Key`, `TTFT`, `JSON`, `ZIP`)
4. ข้อความโครงสร้าง (`" หรือ "`, `"{value}K"`, `"{n} วัน"`, ชื่อหน่วย) ให้คงรูปหรือเติมได้
   เฉพาะกรณีที่อ่านเป็นประโยคได้
5. ป้ายสั้น (ปุ่ม/แท็บ) ให้กวนด้วยการเลือกคำใหม่ ไม่ใช่การเติมคำท้าย

### การแบ่งงานเขียน

เรียง namespace ตามจำนวนคีย์จากมากไปน้อย ทำเป็นชุด ชุดละ 3–5 namespace หรือประมาณ
400–600 คีย์ต่อรอบ บันทึกความคืบหน้าใน `_progress.json` เพื่อทำต่อได้ถ้าเซสชันขาด

## ทางเลือกที่พิจารณา

- **แยกพจนานุกรมเป็นไฟล์ JSON แล้วโหลดตอนรัน** — ตัดออกโดยผู้เขียน: DSH โหลด client plugin
  เป็นบันเดิลเดียว ไม่มี fetch ตอนรัน และกฎโปรเจกต์ห้ามเพิ่มที่เก็บข้อมูล
- **ใช้ `zh` เป็นตัวสำรองของ `th` แทน `en`** — ตัดออกโดยผู้เขียน: ระบบบังคับให้สายสิ้นสุดที่ `en`
  และผู้ใช้เลือกเองว่าให้ไทยที่ขาดแสดงอังกฤษ
- **สร้างภาษาใหม่ต่อโทน (เช่น กวนเบา/กวนหนัก)** — ตัดออกโดยผู้เขียน: ตัวเลือกภาษาใน UI
  จะรก และยังไม่มีข้อมูลว่าผู้ใช้ต้องการหลายระดับ
- **ให้ AI สร้างคำแปลกวนทั้งชุดในรอบเดียวแล้วไม่ตรวจ** — ตัดออกโดยผู้เขียน: ตรวจสอบไม่ได้
  และผิดกฎความจริงของโปรเจกต์

### การยืนยันผลบนเครื่องจริง

1. คัดลอกไฟล์ไป `/storage/emulated/0/AI storage/dsh-thai-locale`
2. ตรวจว่า `node_modules/dsh-thai-locale/package.json` เห็นเวอร์ชัน 1.3.0 (ลิงก์เดียวกัน)
3. โหลดหน้าเว็บใหม่ แล้วเปิด การตั้งค่า → ภาษา ต้องเห็นตัวเลือก `ไทย (กวนตีน)`
4. เลือกแล้วตรวจว่าไม่มีคีย์แสดงเป็นคีย์ดิบ (เช่น `chat.foo.bar` ขึ้นบนจอ)
5. ถ้า UI ไม่เปลี่ยน ให้อ่านบันทึกของแอปแล้วรายงานตามจริง ไม่เดา
