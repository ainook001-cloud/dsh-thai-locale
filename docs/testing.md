# การทดสอบโปรเจกต์นี้

โปรเจกต์นี้เป็นชุดคำแปลล้วน ไม่มี UI ของตัวเอง จึงแบ่งการทดสอบเป็น 3 ชั้น

## ชั้นที่ 1 — ตรวจรูปแบบอักษร (มีแล้ว)

```bash
node tools/check-translations.mjs    # คีย์ 4,601 ตรวจอักษรต้องห้าม/รูปแบบเสีย
node tools/check-roast.mjs           # ตรวจคุณภาพชุดกวน (placeholder, คำท้ายซ้ำ, ความยาว)
node tools/check-coverage.mjs        # เทียบ th กับ th-roast + ซอร์ส zh/en ของเอนจิน
```

`check-translations.mjs` ตรวจได้: อักษรจีนหลุด, อักษรลาวที่หน้าตาคล้ายไทย, วรรณยุกต์ซ้ำ,
วรรณยุกต์มาก่อนสระ, พยางค์เริ่มด้วยเครื่องหมาย, คีย์ไม่ใช่สตริง

`check-roast.mjs` ตรวจได้: placeholder ไม่ตรง, อักษรจีน/ลาว, คำท้ายซ้ำ, ป้ายสั้นที่เติมคำท้าย,
ข้อความไม่อยู่ในรูป NFC, คีย์หาย/เกิน

`check-coverage.mjs` ตรวจได้: คีย์ th กับ th-roast ตรงกัน, เทียบกับซอร์ส `zh`/`en` ของแพ็กเกจเอนจิน
(จับคู่ได้ 8 namespace / 143 คีย์ ตรงทั้งหมด), คีย์ที่ไม่มีต้นทาง

ตรวจไม่ได้ทั้ง 3 ตัว: คำแปลอ่านแล้วเป็นธรรมชาติหรือไม่ (ต้องใช้คน)

## ชั้นที่ 2 — รันโค้ดจริง (มีแล้ว)

```bash
node --test tests/*.test.mjs
```

โหลด `lib/client.js` จริงเข้า `vm` sandbox จำลอง `window.__ModuleLoader__`
และ `ctx.locale` ของ DSH แล้วตรวจสอบผลลัพธ์ **10 ข้อ**:

| # | ตรวจ |
|---|---|
| 1 | ลงทะเบียน entry เดียวชื่อ `dsh-thai-locale` |
| 2 | `addLanguage` ถูกเรียก 2 ครั้ง: `th` (fallback `en`) และ `th-roast` (fallback `th`) |
| 3 | ลงทะเบียนครบ 75 namespace |
| 4 | ทุก namespace มีคีย์ไทย และ namespace ที่เขียนกวนมี `th-roast` |
| 5 | `setLocale("th")` ถูกเรียก |
| 6 | `dispose()` คืนฟังก์ชัน และเรียก cleanup ครบทุกตัว |
| 7–10 | coverage: ไฟล์ต้นทาง `tools/roast-source/` ตรงกับ `thDicts` (คีย์/placeholder) และบล็อก `thRoastDicts` ที่สร้างแล้วตรงกับไฟล์ต้นทาง |

ชั้นนี้จับ regression ที่ตัวตรวจอักษรจับไม่ได้ เช่น เผลอแก้ `apply()` จนไม่ลงทะเบียน
หรือทำให้ `dispose` ไม่ทำงาน (จะทำให้ปลั๊กอินค้างหลังปิดใช้)

## ชั้นที่ 3 — ทดสอบ UI บนแอปจริง (มีบางส่วน)

โปรเจกต์นี้ไม่ได้เรนเดอร์ component ของตัวเอง แต่สามารถอ่านข้อความบนจอจริงได้
ผ่านเครื่องมือ `ui` ของ DSH (WebView automation)

**สิ่งที่ทำแล้ว (รอบ COMPLETE-ALL)**

อ่านข้อความบนจอจริงได้ 190–351 บรรทัด 6 หมวดเป็นไทยครบ: เมนูหลัก, สถานะ,
การแจ้งเตือน, ข้อความระหว่างทำงาน, ข้อความแจ้งข้อผิดพลาด, ข้อความจำกัดการใช้งาน

พบข้อความอังกฤษหลุด 3 จุด (`Connection error.`, `TRANSPORT`, `UNKNOWN`)
แต่ไล่ต้นทางแล้วมาจาก SDK ของผู้ให้บริการโมเดล (`@anthropic-ai/sdk`, `openai`)
ไม่ใช่ระบบแปลของ DSH — ปลั๊กอินนี้แตะไม่ได้

**สิ่งที่ยังทดสอบไม่ได้**

| หน้าจอ | ตรวจอะไร | สถานะ |
|---|---|---|
| Settings | ป้ายทุกหมวดเป็นไทย, ไม่มีคีย์โผล่เป็น `settings.*` | นำทางไปหน้าไม่ได้ (เครื่องมือ `ui` ใช้ `goto` ไม่ได้) |
| Chat | ข้อความสถานะเป็นไทย | ทำแล้ว (ผ่าน) |
| Plugins | ชื่อปลั๊กอินทดลอง 22 ตัวเป็นไทย | ยังไม่ได้เปิดหน้าจอนั้น |
| Permission | ปุ่มอนุมัติ/ปฏิเสธ คำอธิบายสิทธิ์เป็นไทย | ยังไม่ได้เปิดหน้าจอนั้น |
| Market | ชื่อตลาด + 23 หมวดเป็นไทย | ยังไม่ได้เปิดหน้าจอนั้น |
| เปลี่ยนภาษา / fallback | เลือก `ไทย (กวนตีน)` แล้วอ่านผล | ยังไม่ได้ทดสอบ — ต้องเข้าหน้าตั้งค่า |

## สิ่งที่ยังไม่ได้ทำ

- ทดสอบเปลี่ยนภาษา/fallback บนจอจริง (ต้องเข้า การตั้งค่า → ภาษา → เลือก `ไทย (กวนตีน)`)
- เปิดทุกหน้าจอแล้วเทียบกับ `TRANSLATION_STATUS.md`
- ทดสอบติดตั้งบน DSH Desktop
- ทดสอบกับ DSH เวอร์ชันอื่นนอกจาก `0.2.1-rc.2`
