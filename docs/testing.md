# การทดสอบโปรเจกต์นี้

โปรเจกต์นี้เป็นชุดคำแปลล้วน ไม่มี UI ของตัวเอง จึงแบ่งการทดสอบเป็น 3 ชั้น

## ชั้นที่ 1 — ตรวจรูปแบบอักษร (มีแล้ว)

```bash
node tools/check-translations.mjs
```

ตรวจได้: อักษรจีนหลุด, อักษรลาวที่หน้าตาคล้ายไทย, วรรณยุกต์ซ้ำ,
วรรณยุกต์มาก่อนสระ, พยางค์เริ่มด้วยเครื่องหมาย, คีย์ไม่ใช่สตริง

ตรวจไม่ได้: คำแปลอ่านแล้วเป็นธรรมชาติหรือไม่ (ต้องใช้คน)

## ชั้นที่ 2 — รันโค้ดจริง (มีแล้ว)

```bash
node --test tests/*.test.mjs
```

โหลด `lib/client.js` จริงเข้า `vm` sandbox จำลอง `window.__ModuleLoader__`
และ `ctx.locale` ของ DSH แล้วตรวจสอบผลลัพธ์ 6 ข้อ:

| # | ตรวจ |
|---|---|
| 1 | ลงทะเบียน entry เดียวชื่อ `dsh-thai-locale` |
| 2 | `addLanguage` ถูกเรียกด้วย `id: "th"`, `fallback: "zh"` |
| 3 | ลงทะเบียนครบ 75 namespace |
| 4 | ทุก namespace มีคีย์ภายใน |
| 5 | `setLocale("th")` ถูกเรียก |
| 6 | `dispose()` คืนฟังก์ชัน และเรียก cleanup ครบทุกตัว |

ชั้นนี้จับ regression ที่ตัวตรวจอักษรจับไม่ได้ เช่น เผลอแก้ `apply()` จนไม่ลงทะเบียน
หรือทำให้ `dispose` ไม่ทำงาน (จะทำให้ปลั๊กอินค้างหลังปิดใช้)

## ชั้นที่ 3 — ทดสอบ UI บนแอปจริง (ยังไม่มี)

ยังไม่มี automated UI test เพราะโปรเจกต์นี้ไม่ได้เรนเดอร์ component ของตัวเอง
สิ่งที่ควรทำเมื่อมีคนช่วยทดสอบ:

| หน้าจอ | ตรวจอะไร |
|---|---|
| Settings | ป้ายทุกหมวดเป็นไทย, ไม่มีคีย์โผล่เป็น `settings.*` |
| Chat | ข้อความสถานะ (กำลังคิด/กำลังทำงาน/ผิดพลาด) เป็นไทย |
| Plugins | ชื่อปลั๊กอินทดลอง 22 ตัวเป็นไทยหลังรัน `tools/install-plugin-locales.mjs` |
| Permission | ปุ่มอนุมัติ/ปฏิเสธ และคำอธิบายสิทธิ์เป็นไทย |
| Market | ชื่อตลาด + 23 หมวดเป็นไทย |

วิธีทดสอบที่แนะนำ: เปิดหน้าจอทีละหน้า เทียบกับ `TRANSLATION_STATUS.md`
แล้วบันทึกผล — ไม่ต้องสร้าง framework ก่อน เพราะผลลัพธ์คือ "อ่านรู้เรื่องไหม"
ซึ่งต้องใช้คนตัดสิน

## สิ่งที่ยังไม่ได้ทำ

- automated UI test (ต้องมี headless browser หรือ ให้ DSH เปิดหน้าใน WebView)
- ทดสอบติดตั้งบน DSH Desktop
- ทดสอบกับ DSH เวอร์ชันอื่นนอกจาก `0.2.1-rc.2`
