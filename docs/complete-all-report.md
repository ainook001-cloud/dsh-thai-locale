## P0 — Desktop Compatibility

### ผล: ทดสอบจริงไม่ได้ (Environment Blocked)

**หลักฐานที่วัดได้**

```bash
ls engine/node_modules/ | grep -ci "desktop\|electron"    # → 0
ls -d engine/node_modules/@deepseek-ai/*desktop*          # → ไม่พบ
```

เครื่องนี้มีแต่เอนจินฝั่ง Android ไม่มี DSH Desktop ไม่มี Electron
จึงทำข้อเหล่านี้ไม่ได้เลย: ติดตั้งทดสอบจริง, เปิดใช้งาน, เปลี่ยนภาษา, ทดสอบ fallback บน Desktop

### สิ่งที่ตรวจจากซอร์สได้ (ทำแล้ว)

| หัวข้อ | ผล |
|---|---|
| Locale Bridge | พบ `__DSH_LOCALE__` 1 จุดใน `dsh-client-locale/lib/client.js` ใช้เป็นสะพานอ่าน `languages` + `preference` จากโฮสต์ |
| ไม่มีสะพานแล้วพังไหม | ไม่พัง — ตกไปใช้ `resolveInitialLocale` → `detectBrowserLocale` → `en` |
| Client Plugin Loader | ปลั๊กอินระบุ `dsh.client.platform: "web"` ซึ่ง Desktop (Electron) โหลด Web UI ชุดเดียวกัน |
| Native Shell | ปลั๊กอินนี้ไม่ใช้ native shell เลย มีแต่ `lib/client.js` (ฝั่ง client) กับ `lib/index.js` ที่ว่างเปล่า |

### สรุป P0

โค้ดไม่ผูกกับ Web จน Desktop พัง และสะพาน locale แยกจากกันชัดเจน **แต่ยังไม่มีการทดสอบจริงบน Desktop** จึงคงสถานะใน README ว่า "ยังไม่ได้ทดสอบติดตั้งจริง" และ **ห้ามอ้างว่ารองรับ Desktop**

## P1 — Human Translation QA

178 รายการ อยู่ระหว่างตรวจโดยผู้ช่วยที่แยกบริบท (จะรายงานผลใน `docs/translation-qa-p1.md`)

**ข้อที่พบและแก้ก่อนเริ่มตรวจแล้ว**: `TRANSLATION_REVIEW.md` เดิมอ้างข้อความที่แก้ไปแล้ว 4 จุด (`เกินเวลาอย่างที่ GitHub`, `ใช้มิเรอร์ในจีน`, `กําลังเตรียืมติดตั้ง`, `พื้นทีแว่นเต็ม`) จึงรัน `tools/build-translation-review.mjs` ใหม่ ให้ตรงกับโค้ดปัจจุบัน — ยังได้ 178 รายการเท่าเดิม แต่ค่าตรงแล้ว

**เกณฑ์ที่ใช้ตัดสิน**: "ถูกอยู่แล้ว" = อ่านรู้เรื่อง ตรงบริบท (ถึงจะฟังแปลกนิดหน่อย) หรือเป็นคำทับศัพท์ที่ใช้จริง · "ต้องแก้" = สะกดผิด อักษรเพี้ยน คำไม่ตรงบริบทจนอ่านไม่รู้เรื่อง หรือมีภาษาต่างประเทศปนโดยไม่จำเป็น

## P2 — Automated UI Testing

### สิ่งที่ทำได้จริงและทำแล้ว

ใช้เครื่องมือ `ui` อ่านข้อความบนจอจริงของแอปนี้ (DSH Web บน Android) ได้ **302 บรรทัด**

**ผลตรวจ**

| หมวด | ตัวอย่างที่เห็นบนจอจริง | ผล |
|---|---|---|
| เมนูหลัก | เซสชันใหม่, ปลั๊กอิน, เชื่อมต่อ AI, งานอัตโนมัติ, พื้นที่ทํางาน | ไทยครบ PASS |
| สถานะ | กําลังรัน, 3 ซับเอเจนต์กําลังรัน | ไทยครบ PASS |
| การแจ้งเตือน | เข้าสู่ระบบ DeepSeek แล้ว, โหมดมาตรฐาน, 16 ซับเอเจนต์ | ไทยครบ PASS |
| ระหว่างทํางาน | ส่งคําขอไปยังโมเดลใหม่แล้ว (4/5) · 4 วินาที, วิเคราะห์เสร็จแล้ว, รันคําสั่งแล้ว, แก้ไฟล์แล้ว, ประสานงานซับเอเจนต์แล้ว | ไทยครบ PASS |
| แจ้งข้อผิดพลาด | ประมวลผลล้มเหลว, รอบนี้ทํางานล้มเหลว, ใช้ไป 17.4M โทเคน | ไทยครบ PASS |
| ข้อจำกัดการใช้งาน | ใช้ได้เฉพาะข้อความสุดท้ายของเทิร์นที่เสร็จแล้ว | ไทยครบ PASS |

### ข้อความอังกฤษที่หลุด: พบ 3 จุด แต่ไม่ใช่ข้อบกพร่องของปลั๊กอินนี้

บนจอเห็น `Connection error.`, `TRANSPORT`, `UNKNOWN`

**ตรวจต้นทางแล้ว**

```bash
grep -rl "Connection error" engine/node_modules/ --include="*.js"
# → @anthropic-ai/sdk/core/error.js
# → openai/core/error.js
# → @google/genai/dist/node/index.cjs
grep -c "Connection error" lib/client.js          # → 0
```

ทั้ง 3 ข้อความเป็นข้อความ error จาก **SDK ของผู้ให้บริการโมเดล** (`@anthropic-ai/sdk`, `openai`) ไม่ได้อยู่ในระบบแปลของ DSH เลย ปลั๊กอินนี้แตะไม่ได้

### สิ่งที่ทำไม่ได้

- Desktop: ไม่มีให้ทดสอบ
- ตรวจ "ทุกหน้าจอทั้ง 75 namespace" อัตโนมัติ: เครื่องมือ `ui` เปิดถึงเฉพาะหน้าที่นำทางไปถึง ไม่ใช่ทั้งแอป
- ตรวจ Playwright/Selenium: ไม่มีเบราว์เซอร์แยก และโปรเจกต์ห้ามเพิ่ม dependency

### ตรวจรุ่นใหม่กว่า (สำคัญ)

npm มีรุ่นใหม่กว่า `0.2.1-rc.2`: `0.2.2-alpha.2`, `0.2.1-rc.5`, `0.2.2-alpha.3`, `0.2.2-rc.1`, `0.2.2-rc.2`, `0.2.2-rc.3`

ดึง `@deepseek-ai/dsh-client-locale@0.2.2-rc.3` (90,011 ไบต์) มาแกะเทียบ API

```bash
addLanguage        : 1   (มี)
register(          : 1   (มี)
setLocale          : 1   (มี)
assertFallbackChain: 1   (มี)
fallbackChain      : 1   (มี)
exports: COMMON_NS, FALLBACK_LOCALE, LocaleRuntime, SETTINGS_NS, apply, inject
```

**สรุป P3**: API ที่ปลั๊กอินนี้ใช้ **ไม่มีการเปลี่ยนแปลงแบบ breaking** ระหว่าง `0.2.1-rc.2` กับ `0.2.2-rc.3` ค่า `engines.dsh` ที่ตั้งไว้จึงถูกต้องและไม่ต้องแก้

**ข้อควรระวัง**: การตรวจนี้ดูเฉพาะชื่อ API ไม่ได้รันจริงบน 0.2.2 — ถ้าจะยืนยันเต็มรูปแบบต้องอัปเดตเอนจินแล้วทดสอบ

## ข้อจำกัดที่ต้องยอมรับ (ห้ามเขียนกลบ)

1. **Desktop ไม่ได้ทดสอบเลย** — ไม่มีเครื่อง ห้ามอ้างว่ารองรับ
2. **P4 เทียบ source ครบชุดทำไม่ได้** — ไม่มีต้นฉบับอังกฤษครบในเครื่อง
3. **P2 ครอบคลุมไม่ครบทุกหน้าจอ** — เครื่องมือ `ui` เปิดถึงเฉพาะหน้าที่นำทางไปถึง
4. **คําตอบ "COMPLETE-ALL" ต้องนิยามให้ชัด** — ถ้าหมายถึง "ทุก P ผ่านครบ" คำตอบคือ **ทำไม่ได้บนเครื่องนี้** เพราะ P0 ต้องมี Desktop ถ้าหมายถึง "งานที่ทำได้บนเครื่องนี้เสร็จครบ + ข้อที่ทำไม่ได้มีหลักฐานระบุชัด" คำตอบคือ **ได้**
